# 原币净目标编译与逐功能数据（v11）

2026-10-07。v10只能接收固定毛成交量父计划；v11增加从核对后的账户净基础币目标生成可审阅父计划的编译接口。`ExecutionJournal::preview_target` 不写父计划或订单意图、不发送订单。CLI `target-preview` 在编译前运行完整 REST 核对，核对本身仍更新历史/账户证据，并检查核对和编译的时间预算。连续信号→持久目标→自动外部执行的协调器仍未实现，输出快照也不是发送许可。

## 一个目标，三种数量

净仓位是原币账本核对的基础币总资产，包含 free + locked；可下单资源只来自 free；毛量是交易所买卖量，不包含手续费。目标是单个隔离账户的绝对基础币资产，不是某个策略专属仓位。绑定符号、原币资产、账户身份、历史游标、账户更新时间和请求/快照 SHA-256 随预览输出，摘要检测来源变化，不是身份认证签名。

对买入，毛量不超过 `target - net`，并按可用报价币扣掉费用预留后量化到网格；基础币费用会使净量低于毛量，不自动加量补齐。对卖出，毛量加基础币费用预留不能超过 `net - target` 或 free 基础币；报价币费用也先预留，不借用尚未到账的卖出收益。报价币名义金额向上取到 1e-8 单位，委托数量向下量化，不能用小数截断隐藏资金缺口。

两项费用预留是调用方对**整份计划**最大原币费用的假设，单位分别是基础币数量和报价币金额，不是本模块从费率推断的保证；必须包含所有部分成交/逐成交舍入费用。第三币种费用、折扣/费率变化、实际手续费超过预留、不完全成交和外部活动都可能使预测不成立。输出 `projected_net_low/high`、最坏残量与 `within_tolerance_if_reserves_hold` 只是完整成交且假设成立时的区间，不宣称净目标已实现。v10执行器不持久保存/强制该净目标或费用预留；将预览父计划交给它也不会获得这些保证。

`hold` 表示当前净差已在容差内；`below_minimum` 表示网格量不足配置的每片最小量×片数，或基础币费用预留已超过可买量；`insufficient_resources` 表示 free 资源无法提供最低量。三者都不返回父计划，不能通过悄悄减少片数、扩大容差或向上取整制造订单。`planned` 仍可能因名义上限/资源上限留有明显目标缺口，这时标志是 false。请求名义上限沿用 v10 ≤100 USDT，计划容量/时钟仍受 v10约束。

同一个已有父计划/意图账本不能编译第二个计划，避免靠新ID绕过未知订单。每次进程打开需要重新核对；缺账户/历史绑定、不可交易快照、最新快照与原币账本冲突、数据范围/网格错误都拒绝。库调用者必须在预览前完成新核对并自行控制时间预算；CLI已经实现该边界。

## 运行

```sh
cargo test --locked --test external_target
cargo build --locked --release --example net_target_demo
target/release/examples/net_target_demo reports/my-net-target
cargo build --locked --release --features network --bin kaze-testnet
target/release/kaze-testnet JOURNAL target-preview TARGET.json
```

`configs/net-target-preview.json` 是固定手算 fixture 配置（BTC价格100、数量网格0.01），用于 demo；实际请求必须根据真实行情/工具过滤规则修改，不能当作当前 BTC 交易参数。CLI 输出在 `target_preview` 中，预览的 `plan` 符合既有 PlanConfig；当前不会自动调用 plan-init/tick。把计划手工执行之前仍需核查当前状态和交易所过滤规则，后续 tick 继续完整核对；费用/净目标假设尚未被外部执行协调器强制维护。[外部执行边界](EXTERNAL_PLAN.md)。

## 性能与回归

所有计时为 release，Apple M5/macOS26.5.2 arm64、Rust1.99.0/LLVM23.1.1、thin LTO/单codegenunit。纯分配性能与账户核对/SQL路径分开报告；每轮数据、二进制和固定配置/公开行情身份都公开。新组件首次测量没有旧版本，不能把朴素oracle称作上一版功能。

新增分配组件：4096个确定性输入、每轮100万次、七轮交替。生产整数公式包含边界校验和区间诊断，中位18.639584ms；朴素数量oracle最多枚举128个lot，仅返回毛量，中位191.309916ms，相对该基线约10.26倍。每个输入和每轮数量校验和一致。[全部轮次](evidence/v11/allocator.json)。计时不包括十进制解析/JSON、CSV、SQLite、网络、策略信号；不能读成逐订单延迟或平台加速倍数。

本轮同时交替重测旧/新版的完整持久mock计划与公开纸面负载，结果写入[逐功能数据表](evidence/v11/feature-scorecard.json)，原始[计划对照](evidence/v11/plan-pairs.json)、[百万报价与持久确认](evidence/v11/paper.json)、[纸面交替对照](evidence/v11/paper-pairs.json)。无论变快还是退步都保留，原始完整证据/回执必须一致；不以未测原因解释差异。批次耗时不等于逐报价分位数。

## 门槛与后续

测试网官网仍显示维护；本轮没有真实成交或费用扣除，新增CLI预览尚未在真实账户验收。真实三片、真实部分成交、新版本24h、独立盈利留出门槛仍未通过。下一步先恢复真实测试网闭环，再开发同事务持久净目标/费用反馈和重启协调器；在此之前不要把预览结果当成连续策略执行服务。

架构参考 [NautilusTrader Portfolio 官方文档](https://nautilustrader.io/docs/latest/concepts/portfolio/)（访问2026-10-07，latest可能变化），借鉴原币状态与查询的边界，自行实现整数目标编译。当前没有它的多账户估值/换汇/PnL生态，没有vn.py/ABU/Barter整平台同条件性能结论。

每轮新增功能今后都按“功能→原状态→验证数据→性能前后变化→范围/代价→未通过门槛”交付，已写入AGENTS.md；不得为获得漂亮数字改变固定负载或隐瞒回退。
