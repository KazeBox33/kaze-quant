# vn.py能力对齐与开发顺序

目标是逐项构建可验证的量化平台能力。Rust组件更快不等于整个产品更成熟；以下“已有”仅针对写明的资产、模型与接口范围。每轮以FEATURE_SCORECARD原始数据验收，性能和经济规则分别对照。

## 固定参考

本轮重新查询官方仓库HEAD并检查源码：
- [vn.py核心](https://github.com/vnpy/vnpy/tree/c6e231caf32b7fc97e6459817fff66458cf7e7c4)，事件、主引擎、网关与应用扩展。
- [CTA扩展](https://github.com/vnpy/vnpy_ctastrategy/tree/7a8768de9784dda35a7b261a7ade1dbfbff50919)，模板、回调、本地停止单与回测。
- [CTA使用文档](https://www.vnpy.com/docs/cn/community/app/cta_strategy.html)。应用分布在独立仓库；不把核心仓库当全部生态源码。

## 逐项状态

| 参考能力 | KazeQuant状态 | 对齐工作与验收 |
|---|---|---|
| 事件/委托/成交/账户引擎 | 已有有界同步纸面事件、整数账务、提交顺序、资源冻结；测试网原币账本独立 | 补共享账户、多策略所有权与统一路由；不能直接拼接两个账本 |
| CTA模板与持久策略 | 已有版本化注册、报价/成交/提交反馈、目标仓位、因果bar/ATR | v15增加条件回调与breakout-bracket；后续独立init/start/stop与策略级暂停 |
| 本地停止单 | v15纸面bid/ask阈值、停止限价意图、到期、等待阶段OCO、条件ID到订单ID映射 | 等待不冻结、激活重风控、严格下一报价成交；尚无交易所原生stop/OCO |
| CTA回测与优化 | 已有确定性L1回放、成本压力、冻结训练/测试与walk-forward | 增加可恢复并行实验、参数搜索资源预算、统一成交与风险统计；无tick级外部队列真实性 |
| 算法执行 | 已有纸面累计TWAP和排他测试网固定计划/净目标预算 | 下一轮Iceberg显示量与父子恢复，其后BestLimit报价跟随/替换；逐事件核对共享流动性 |
| 组合策略/资金管理 | 多资产独立预算、单资产目标编译 | 缺共享现金、策略子账、组合NAV/风险；先实现所有权，再组合分配与归因 |
| 行情/数据管理与录制 | L1公开数据校验、事件时间网格、实时纸面、L2原子帧与缺口锁定 | 数据目录/质量报告、bar存储查询/复用、断点导入；多源日历与复权缺失 |
| 多网关/中国期货股票等 | 仅Binance Spot Testnet、公共报价；模型只做多现货 | 必须各自实现合约乘数/保证金/交易日历/订单规则并验收；不能给接口改名便宣称支持 |
| 风控、日志、恢复 | 资金/持仓/价格/容量/陈旧/回撤，SQLite原始回执、检查点、SHA链、备份 | 特色是候选状态事务提交与逐回执复验；链不是认证签名，尚无高可用多节点 |
| GUI、图表、人工交易 | CLI/JSON报告 | 后续只读监控面板与回放诊断，再显式受控操作；尚无桌面工作台 |
| 脚本/RPC/研究扩展 | 可信Rust注册；无Python用户SDK、RPC服务 | 保持执行核心边界，增加只读研究接口/Arrow或文件交换，验证跨语言开销 |
| 价差、期权、因子/ML、Excel生态 | 未实现 | 需要相应市场模型/定价/研究依赖；列入长期路线，当前不宣称替代 |

## 实施顺序

1. **v15已实现：本地条件引擎与可运行CTA策略。** 恢复、去重、失败回滚、真实进程强杀、稀疏/密集选择与固定上游源码组件对照。
2. **下一块：统一父子算法执行。** Iceberg、BestLimit在已有TWAP上统一报告与恢复；以部分成交/撤单/反向目标和父计划守恒验收。先纸面模型，再排他测试网路由。
3. **策略生命周期与所有权。** 多策略路由、策略级停止、订单与条件所有者、共享账户子账，不让某策略误操作别人的单。
4. **组合资金/风险。** 可核对组合估值、分配、换仓、费用归因；缺行情拒绝估值，不从卖单意图虚增可用现金。
5. **数据与研究服务。** 可复用bar/质量目录、资源受限并行研究、跨语言入口与可视化监控。
6. **按市场逐个扩展。** SDK/规则/真实数据和账户条件齐备后实现，不以纸面测试替代实盘验收。

## 比较纪律

组件比较固定输入、版本、原始轮次和语义域，保留性能退步。v15对照的上游函数只执行“没有停止单触发”分支，未导入完整vn.py，也不含网关、策略线程、账户或持久化；结果只能说明这条组件路径。公开百万行情用来证明可运行性和成本，不能证明策略盈利或全平台超越。原有非零真实费用、真实部分成交、新版本24h、独立alpha和主网门槛仍需分别完成。
