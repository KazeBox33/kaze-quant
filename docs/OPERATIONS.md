# 0.3 事务运行、监控与恢复

当前推荐入口为 `kaze-run`，原来的 `kaze-paper` 文件 WAL 路径保留用于学习和性能对照。二者不互相隐式转换。

```sh
cargo build --locked --release --bins
# 批次提交、确认后输出 JSON 回执；EOF 保留会话，finish 显式封闭。
target/release/kaze-run --config configs/paper.json --db reports/session.db \
  --input data/paper.jsonl --finish --verify-full --report reports/first.json
# 不覆盖已有备份或报告。
target/release/kaze-run --db reports/session.db --recover-only --verify-full \
  --backup reports/backup.db --report reports/recovered.json
target/release/kaze-run --db reports/backup.db --recover-only --verify-full \
  --report reports/backup-checked.json
```

默认批次最多 256 条，首条进入当前批次后 5ms 触发提交，EOF 也会提交不足一批的命令。stdin 静默不会让部分批次永久等候；计时是本地处理/调度约束，不是硬实时承诺。输入通道最多 256 条，单行 <=8192 bytes。stdout 全部回执在事务成功后发送，阻塞 stdout 将停止继续消费；如发送失败，命令可能已提交，应重投相同 seq/payload。解析失败会丢弃当前尚未确认批次，先前批次保持有效。业务拒单仍是有回执的命令。

`--batch-size` 可在 1..=StoreOptions.max_batch 中选取，不改变交易语义；低流量用短 deadline，高吞吐接受批次等待。`--quiet` 适用于文件回放基准，不向外部生产者提供确认通道。`--quotes CSV` 将规范化单资产 QuoteReader 输入映射至 market=0、全局 seq=quote.sequence；已有人工命令混入的会话应使用 JSONL，不可直接混用 CSV 序号。

单位元数据必须与适配器一致：`price × quantity = money minor`。BTC 示例每货币 100000000 minor、每 BTC 100000 lot，价格整数值 = USDT/BTC × 1000。账户金额以字符串表示，序号/纳秒为 u64。客户端不能用损失精度的 JavaScript Number 解析大纳秒值。

## 资源与健康

默认 `StoreOptions`：终态保留每资产 64 条、最大批次 256、生命周期命令 <=10^12、数据库 1 GiB、WAL 软限 64 MiB。可通过 `--store-options PATH` 传严格 JSON；所有选项绑定 manifest，恢复时必须相同。数据库页配额用 SQLite max_page_count，WAL 达到软限请求 truncate checkpoint，读者持有旧快照则反压拒绝当前批次，不无限增长。WAL 允许一批有界超调，理论上限由 64MiB 状态与每批命令/回执上限共同决定；软限不是严格文件字节上限。

报告 `storage_stats` 给出逻辑数据库大小、WAL 字节、热检查点字节和限额，`run` 给出处理时间、确认批次数与有界直方图。直方图是每批事务执行时间，排除排队/stdout；bucket i 上界 2^i ns，最后桶为溢出桶。它不是逐命令完整确认延迟分位数。容量告警/周期审计/备份调度由调用方执行；CLI 不偷偷创建后台任务。

存储写入/提交错误会 poison 当前 session：保留已有已确认状态，不继续写入，退出并恢复确认结果不确定的输入。数据库满需归档或按预先规划的新会话处理；不要删历史、修改 meta 或清除旧持仓绕开配额。当前没有就地扩容、历史归档轮换或跨会话持仓迁移命令。

## 检查与备份

快速恢复读取经过 SHA-256 校验的热检查点，验证账号守恒、冻结、订单身份/顺序、策略窗口、时钟和尾高水位。性能主要随热状态与剩余 SQLite WAL 变化，而非完整 commands 表长度；未承诺绝对常数时间。定期用 `--verify-full` 扫描所有命令、链、回执并重建最终状态。快速启动没有扫描的中间损坏可能延后到审计才发现；不把快速检查描述为完整数据健康证明。

在线备份使用 SQLite Backup API，再 sync 与不可覆盖发布，包含同一事务版本的状态和审计。正在运行的 WAL 数据库不能只复制 `.db` 文件；不要替换、删除 `.db/-wal/-shm/.lock`。SHA 链检测意外修改，不防具备写权限的攻击者重新计算所有哈希；整份数据库回滚到旧合法备份需要外部确认高水位/链摘要识别。

Mac 可以作为第一阶段开发和纸面运行机器，SQLite bundled 避免依赖机器上预装库。Linux CI 验证同一整数模型；迁移硬件必须复测吞吐、同步、内存和恢复。manifest 绑定二进制，所以 Mac 的数据库不能由 Linux 新二进制直接续写；当前迁移方式是保留规范化完整输入并在目标环境重新回放、核对账本，在新的运行身份下继续实验。跨平台继承真实资金会话的迁移工具尚未实现。

WAL 依赖同主机本地文件系统；不部署到网络共享盘。测试覆盖进程 kill、SQL 写失败、真实页配额满和读者阻塞，不覆盖实际断电/控制器缓存故障。当前验收目标是可恢复的确定性回放/纸面运行，不包含实盘 venue 或交易所保证金语义。

# 纸面运行与恢复手册

## 构建与运行身份

使用仓库锁文件、固定工具链和 `cargo build --locked --release --bins`。部署时一起保存二进制、配置、输入来源、仓库提交及 WAL。manifest 绑定实际二进制 SHA-256、规范化配置 SHA-256、schema 与执行规则版本；保留同一可执行文件比“重新编译相同源码”更严格。

`kaze-paper --help` 查看参数。默认配置 `configs/paper.json`；默认 WAL `reports/paper.wal`；默认 stdin。文件数据从 `--input PATH` 读取，完成报告的路径必须全新。stdout 是逐命令 JSON 回执，stderr 是启动恢复信息/错误，退出码非零表示输入、存储或报告失败。业务拒单记录在回执和状态指标中，不等于进程异常。

## 命令协议

每行最多 8192 字节。UTF-8 JSON，无注释；未知字段/枚举、非法 Price/Quantity、错误资产索引或倒退时间均拒绝。`seq` 是调用者指定的全局编号，从 1 起连续；`quote.sequence` 是每资产报价编号，可以有间隔。

```json
{"seq":1,"command":{"type":"quote","market":0,"quote":{"sequence":1,"timestamp_ns":1000000,"bid":9900,"ask":9910,"bid_quantity":10,"ask_quantity":10}}}
```

提交订单（常量枚举字段大小写如示例）：

```json
{"seq":2,"command":{"type":"submit","market":0,"request":{"side":"Buy","limit":10000,"quantity":2,"time_in_force":"GoodTilCancelled"}}}
```

撤单、watchdog、人工停止、封闭会话：

```json
{"seq":3,"command":{"type":"cancel","market":0,"order_id":1}}
{"seq":4,"command":{"type":"advance","timestamp_ns":1000000001}}
{"seq":5,"command":{"type":"halt"}}
{"seq":6,"command":{"type":"finish"}}
```

示例配置启用自动策略；若由外部信号发送订单，应将策略设为 `{"type":"passive"}`，避免两套信号同时占用预算。报价发生后内置策略可能已提交订单，因此不能假定手工提交的第一张订单编号一定是 1。

所有金额为分，数量为整数资产单位。账户金额/费用在纸面 JSON 中为字符串；协议编号与时间是 u64，外部 JavaScript 等客户端应采用支持大整数的解析方案。

## 确认、重试、背压

校验成功后 WAL 先写入完整命令并 `sync_all`，然后处理订单/账户/策略，最后发回执。不先确认再写日志。若进程在同步后、发送回执前中断，恢复仍会处理该命令；调用者应重投相同编号和相同内容。

已有编号内容相同时回执 `duplicate=true`，不再次执行，也不重复输出旧成交事件。要检查经济结果，读取恢复报告。相同编号不同内容、序号缺口直接失败；不能更换 payload 复用已经确认过的编号。

stdin 按行顺序读取、每条处理完成才读取下一条；操作系统 pipe 加上生产者等待确认提供背压，无后台无限队列或静默丢弃。输入生产者与持久回执通道应同时保持可用。stdout 失败时命令可能已经持久处理，应按原编号重试。

## 行情健康与风控

报价/`advance` 检查所有资产是否超时。超过 `max_quote_age_ns` 才触发，边界相等允许。先撤单再安装新报价，防止旧委托跨越行情断档后被模拟成交。静默期间适配器必须定期发送模拟时间轴的 `advance`；本平台不会偷偷把墙钟混入回放。真实网络接入需要另写 watchdog 时间转换与健康状态适配。

达到绝对回撤阈值、人工 halt 或动作缓冲溢出时暂停、撤销所有该资产委托，保留实际持仓；后续报价仍更新估值，但不再生成/接受订单。回撤基于 bid 标记权益高点，含已支付费用，不包含尚未发生的平仓费用。

暂停是当前会话的锁定状态。再次运行或提供新报价不会自动解除风险；不要通过新预算会话掩盖旧持仓风险。跨会话继承、风控重置与实盘减仓尚未实现，应先结束实验并独立处理剩余仓位。

## 恢复与损坏

启动使用同一 WAL 获取排他文件锁，读取完整日志、验证 SHA-256 链和命令连续性、重放并执行账务不变量检查。`--recover-only` 会执行恢复，包括下面的尾帧修复，并不是纯只读检查。

- 只有最后一帧缺少长度/载荷/哈希的完整字节时，备份 suffix 为 `.torn-<sha256>`，再截到最后完整帧；回执里未确认的命令可重投。
- 完整帧哈希不匹配、长度超限、结构/语义错误、版本/二进制/配置不符：返回错误，原 WAL 不截断、不跳过。保留原文件进行诊断。
- 不完整 manifest 不能自动猜测修复。保留文件，确认它未产生有效会话后使用新路径。
- 写入或同步失败会使当前对象永久 poisoned；不应用该次命令，不再接收后续命令。关闭并检查存储后恢复，处理确认结果不确定的命令。

哈希链用于检测意外修改、内部删除或乱序，**不是认证签名**。删掉整个有效尾帧可留下合法前缀，仅靠本地文件无法证明更高的历史高水位。外部保存确认编号和链摘要，才能核对这种情况。进程强杀测试不等于断电/控制器缓存故障验证；可靠性取决于操作系统/存储对 sync 的实现。

## 容量与报告

最多 64 资产；总订单历史容量与总策略窗口均 <=100 万；命令数量 <=100 万；WAL <=512 MiB；帧 <=64 KiB；配置文件 <=256 KiB。订单记录/活跃索引、窗口和命令身份摘要有边界，恢复逐帧读取，不把整个日志读进内存。达到命令/日志容量会停止接收；订单历史满时产生平台拒单。

这是有界会话设计。没有日志轮换、账户/持仓迁移、快照加速或无限运行保证。不要删除 WAL/重置配置来消除持仓与历史限制；保留报告与日志，按独立实验/会话管理容量。

JSON 报告是某一高水位的状态检查点/观察结果，不是恢复输入。`closed=false` 表示 EOF 时会话未封闭。`--finish` 会追加持久 finish；之后只允许重试以前的命令。文件通过新临时文件 + sync + 不可覆盖的 hard_link 发布；文件系统不支持锁、硬链接或必要同步时直接失败。操作期不要删除、替换或复制正在写入的 WAL，所有写入者必须遵守同一排他协议。

如要线上使用当前纸面模式，先在目标 Linux/文件系统执行测试、留存二进制并验证恢复时间和资源预算。真实交易生产化还需要 venue 适配、订单/成交对账、身份与权限控制、长期数据验证，以及独立的存储故障/负载验证。


## 0.6条件运行容量

等待条件独立有界；单条SQLite回执8MiB、整批编码回执16MiB、检查点64MiB，仍受磁盘/WAL配额约束。大规模多资产同时间触发可能整批容量拒绝，确认前不前移输入高水位；拒绝批次不输出成交确认。策略Paused保留持仓，停止限价跳空不保证成交，见[CONDITIONAL_ORDERS](CONDITIONAL_ORDERS.md)。旧会话只能由原二进制恢复，不删除manifest或修改执行版本绕过绑定。
