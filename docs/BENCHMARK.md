# 性能实验记录

日期：2026-10-04；硬件 Apple M5，arm64；macOS 26.5.2；Rust 1.99.0 (b940084d7 2026-09-28)。

编译使用 Cargo release 默认优化、thin LTO、codegen-units=1；未启用 target-cpu=native。单线程，没有绑核、固定频率或隔离系统负载。

每个组合预热一次、重复 7 次、交替优化/对照的运行顺序。表中是整批操作中位耗时，不是逐事件延迟。计时排除数据生成、引擎/窗口创建、文件输出和完整历史审计。事件 sink 为 ()，不保存事件。

订单计时仍包含报价处理、策略外的提交动作、风控、账户更新与工作量计数；churn 包含结束时撤单，all-active 只包含 10000 次报价处理。不同负载不能直接横向比较吞吐。

## 如何解释

order_churn：每条报价尝试执行前一张订单，再提交一张单位数量的买/卖单，最多一张活跃订单。20000 条报价下，历史扫描触碰 199990000 条记录，活跃版本触碰 19999 条，工作量差为 10000 倍；时间差约 883 倍。这是刻意展示历史累积瓶颈的合成负载，不代表真实交易系统整体速度，也不是与 NautilusTrader/HftBacktest 的比较。

all_active：1000 张未穿价 GTC 订单始终活跃，处理 10000 条报价。双方都扫描 10000000 条记录；索引不带来工作量优势。首次测量活跃版本比对照慢约 1.9%，因此加入所有记录活跃时的连续扫描路径。复测差距约 0.75%；这是小幅差异，可能受编译布局/计时噪声影响，不能证明完全消除了开销。

滚动均值：200000 次更新，窗口分别为 16/256。增量和替换全窗口重算，所有输出的累计校验和相同，单独测试也逐输出核对。窗口 256 时约 27.6 倍，窗口 16 时约 2.14 倍。这里没有 SIMD 或多线程，收益来自减少重复计算。

小规模 batch 容易受预热、CPU 频率、缓存与调度影响；原始 min/max 数据保留了波动。不能从这些数字声称实盘 tick-to-order 延迟、p99 或网络延迟已经得到验证。没有采集硬件缓存未命中计数，也没有用 RSS/分配探针测量热路径内存。

## 正确性与原始证据

- 扫描优化：12 个固定种子、共 3000 条混合报价，逐事件比较日志、订单、账户和权益；另有手算执行账本与边界测试。
- 两种扫描版本共用 try_execute/account，因此对照不独立证明所有执行逻辑；手算与不变量补充验证。
- 原始数据：[连续扫描路径加入前](benchmarks/before-dense-path.csv)、[加入后](benchmarks/after-dense-path.csv)。前者使用 6511bff 的核心和当前 benchmark 驱动，后者核心代码提交 b592a46。
- CSV 的 samples/min/median/max 为批次统计，checksum 为计算结果校验；不等同于对整个账户状态的哈希。

## 有界 L2 订单簿实验（第三阶段）

核心与驱动提交 5b0ccc8，环境和重复方式同上；每侧最大档位数分别为 16/64/1024/8192，每批 100000 次更新。计时不含初始构簿、数据生成和对照验证。更新流约 1/8 为删除，其余为数量替换或重新插入；簿会暂时稀疏。两个版本均执行序号、时间、数量、交叉价格与容量校验。

| 每侧档位上限 | 有序 Vec 中位 ms | BTreeMap 中位 ms | BTreeMap / Vec |
|---:|---:|---:|---:|
| 16 | 1.624791 | 3.527834 | 2.171x |
| 64 | 1.466375 | 2.637167 | 1.798x |
| 1024 | 2.975833 | 3.615334 | 1.215x |
| 8192 | 13.928958 | 4.942083 | 0.355x |

64 档有序 Vec 约快 1.8 倍；8192 档有序 Vec 约慢 2.8 倍。二分查找不消除插入/删除的 O(n) 移动成本。项目的 64 档示例用有界数组解释连续布局；若需要大型深度簿，应重新测量树、分块数组或其他结构。这不是全规模最优实现。

在计时前，对每个规模的完整流逐 Quote 与独立 BTreeMap 实现比较；另外 8 个种子、16000 次更新的测试比较全深度与最优报价。原始数据：[订单簿实验](benchmarks/order-book.csv)。

## 0.2 同步纸面持久化成本（2026-10-06）

环境仍为 Apple M5 / arm64 / macOS 26.5.2，Rust 1.99.0 release、thin LTO。运行 `cargo run --locked --release --example paper_bench -- 2000`；原始数据见 [paper CSV](benchmarks/paper-apple-m5-2026-10-06.csv)。三轮，每轮2000命令，quote/buy/quote/sell循环，1单位IOC、零价差、零费，单资产passive。每个命令单独用 Instant 计时；检查全部状态与独立内存运行一致，再检查恢复结果。没有将整个批次时间除以事件数伪装为p99。

| 模式 | 三轮批次耗时范围 | 每命令 p50 范围 | 每命令 p99 范围 |
|---|---:|---:|---:|
| PaperRuntime 内存处理 | 0.290–0.385 ms | 125–167 ns | 208–209 ns |
| DurableSession 每条 sync_all | 8.001–8.031 s | 3.997–3.999 ms | 4.293–5.938 ms |

恢复2000命令含二进制hash与全部重放约17.1–18.5ms，时钟测量打印在stderr。持久路径的瓶颈在当前文件系统同步；不能把内存计时数字当作磁盘持久确认、真实网络或交易所延迟。

这是非常小的合成订单负载，包含回执构造但不包含stdout传输、外部信号计算和网络。未绑核、未测硬件计数、首轮无独立预热；每条 timer 开销对亚微秒内存样本有明显影响。三轮样本仅说明当前环境的成本差别，不提供线上尾延迟保证。WAL 在临时目录测试，不能外推目标服务器存储。

BookFeed 帧级双缓冲不在旧单档订单簿基准范围内；它以O(depth)复制换原子帧验证，须用真实frame/depth负载另行测量。
