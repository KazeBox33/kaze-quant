# 执行内核与平台运行契约

## 资产与数值范围

- 每个 Engine 管理一个现货资产、一个独立预算账户，只做多，无杠杆、做空、资金费和融资利息。PaperRuntime 按稳定整数索引组合多个 Engine，不引入共享融资。
- Price：1..=10^12，单位为分；Quantity：1..=10^9 整数资产单位。
- 账户金额、手续费和估值使用 i128；初始现金 0..=10^30；历史订单最多 10^6。
- 一笔成交额不超过 10^21 分，整段历史成交额不超过 10^27 量级，远小于 i128 边界。
- 费用按每次成交额的 bps 计算，向上取整到分；fee_bps 为 0..=10000。
- Engine 值类型只约束数值范围。PaperRuntime 在边界增加配置的整数 price_tick / quantity_step 网格；未实现小数资产、合约乘数和交易日历。

## 每条报价的执行顺序

1. 检查报价：价格有效、bid <= ask、数量有界、sequence 严格增加、timestamp_ns 不下降。
2. 安装当前模拟报价和时间。
3. 按自己订单的提交先后，处理已满足延迟且提交 sequence 小于当前 sequence 的订单。
4. 同一条报价的 bid/ask 可用数量在自己的订单之间共享。
5. 买单 limit >= ask 时按 ask 成交；卖单 limit <= bid 时按 bid 成交；数量取剩余量和可用量的较小值。
6. 更新真实成交对应的账户和订单，发出 Fill。IOC 在首次可执行报价上尝试后撤销剩余量；GTC 继续等待。
7. 稳定压缩活跃索引，按 bid 对持仓估值并更新权益高点/最大绝对回撤。
8. CSV replay 策略产生一个动作；PaperRuntime 在只读视图上生成有界批量动作，按顺序逐笔重新风控与执行。

零延迟也不能在产生订单的同一条报价成交。时间戳可相同，但 sequence 必须增加。同一价格上的外部排队未建模；这里的提交优先只决定自己的订单如何共享模拟报价数量，不代表交易所的排队规则。

## L2 深度模块

OrderBook 由两个升序、预分配 Vec<Level> 拥有两侧价位。DepthUpdate 的数量表示该档位的替换量，零表示删除；读最优 bid/ask 为 O(1)，定位档位为 O(log n)，插入/删除移动元素为 O(n)。它适合有限深度；8192 档的实验明确显示移动成本，见性能报告。

每次更新先检查数量、跨边价格、容量、模拟时间和连续 sequence，再修改。失败不改变档位和时钟，可修正同一 sequence 后重试。删除不存在的档位是幂等操作，仍推进序号。只有双边都非空时才生成 Quote；空边不会伪造价格。

该序号是一个人为定义的全局“每档更新”序号。真实行情的一帧多档位、同一帧共同序号、快照/增量衔接需要协议适配；检测缺口后目前只报错，重建需调用方新建 OrderBook。引擎不会因为自己的成交改写外部历史簿，仍受报价流动性刷新假设限制。

## 资金冻结与订单状态

买单冻结：quantity × (limit + fee(limit, bps))。fee 在单单位金额上取整，这比整单计算保守，但能覆盖任意整数数量拆分产生的费用。若每次费用小于一分，拆成多次成交仍需逐次付一分，不能只冻结整单费用。

每次买入成交，按成交数量释放冻结额，扣实际成交额与手续费，增加持仓。价格优于 limit 时，多冻结的部分自动恢复可用。未成交撤单释放剩余冻结额。卖单冻结的是可卖持仓；提交卖单不会立即减少已成交持仓。

状态允许：

```text
Accepted → PartiallyFilled → Filled
   │              │
   └── Cancelled ←┘
Rejected 为终态
```

Cancelled 保留未成交 remaining，用于审计；Filled 的 remaining 必须是零。重复撤销返回 false，不重复释放资源。回放结束撤销所有活跃订单，不自动清仓。最终权益包含按最后 bid 估值的持仓，未扣尚未发生的平仓手续费。

## 风控与错误

- 持仓上限包含已成交持仓和所有待买入数量，不用尚未成交的卖单抵消买入风险。
- 冻结现金不可被其他订单重复花费；冻结卖出数量不可被其他卖单重复使用。
- 活跃订单达到上限时，拒绝新订单；拒绝的记录同样占用历史容量。
- 历史容量耗尽返回 HistoryLimit，不创建新 ID/Event。replay 将其当作运行失败，避免默默得到截断结果。
- submit 的每一个 Result 必须检查。拒绝交易不等于运行失败；容量耗尽、非法数据等是运行错误。
- 非法报价在任何状态改变前被拒绝。CSV 只接受固定表头、六个无符号整数列、无引号；每行最多 4096 字节。
- CLI 成功写完、flush 事件、审计通过后才发布 summary.json 完成标记；出错文件保留 .partial，不发布成功报告。
- 文件日志写错会被 TraceWriter 记录，并在 finish 时返回。它不会回滚此前已执行的模拟事件；部分文件不是成功结果。

## 审计不变量

check_invariants 重新扫描全部历史，独立计算冻结现金、待买数量、冻结卖出量和活跃数量，并核对：

- cash >= reserved_cash >= 0；available_cash >= 0。
- position >= reserved_sell；position + pending_buy <= max_position。
- cash = initial_cash − net_buy_notional − fees_paid。
- Filled 的剩余量为零，活跃订单剩余量为正。
- 活跃索引严格按历史索引增加，包含且只包含所有活跃记录。

debug 模式在状态变更后做审计，因此不适合做性能结论。release 热路径不扫描完整历史；基准在计时完成后主动审计。

## 仿真限制

报价事件刷新时恢复输入给出的显示数量。这不意味着下一条报价代表新成交量；使用高频快照时可能高估可重复消费的流动性。模型不改变未来历史数据，不模拟外部队列、真实撮合规则、市场冲击、网络故障和真实交易费用。latency_ns 只描述提交到最早执行时间；撤单立即生效，不包含独立回报/撤单延迟。

示例策略与演示数据的作用是检验工程闭环。其盈利数值不能用来证明策略具有统计优势。


## 0.2 纸面平台附加契约

- 全局 Envelope.seq 从1连续递增；报价 sequence 在资产内严格递增。报价与 advance 时间全局不下降，同时间事件允许。
- DurableSession 校验输入、记录完整命令并同步，再调用同一 PaperRuntime 处理。校验错误不写日志；业务拒单写入并产生可重放回执。日志确认后崩溃可以重试完全相同的命令，禁止冲突身份。
- 每资产预算独立，(market, order_id) 标识订单。时间推进会检查所有资产超时，撤销过期订单发生在新报价撮合前。
- 绝对回撤达到阈值、超时、人工 halt、策略动作溢出时锁定暂停、释放剩余冻结，持仓不自动清算。finish 撤单并禁止新命令；EOF 不等于 finish。
- 平台风控拒绝不分配核心订单 ID；核心资金/持仓/活跃上限拒绝仍按 Engine 契约创建拒单记录。订单历史耗尽在平台边界拒绝，不调用核心的 HistoryLimit 分支。
- 配置、运行报告、持久日志中的 i128 金额是十进制字符串。轻量 CSV replay 的 v1 summary 保持原有数值字段兼容，消费者需注意大整数精度。
- 恢复绑定完全相同的二进制、配置和执行版本；重放重建策略窗口及风控状态，不依赖观察事件CSV或报告快照。完整帧损坏不跳过；仅不完整尾帧备份后截断。
- SHA链不是身份认证；完整有效尾部丢失须结合外部持久确认高水位/链摘要识别。

BookFeed 提供独立的快照/帧级接口。snapshot 使用严格升序、非重复、正数量档位，重建整本簿；delta 的一个序号覆盖整帧，禁止重复 side/price，先删除后增加、最后验证跨边价格，成功才交换缓冲。检测序号缺口时保留主簿供诊断，健康状态变为 NeedsSnapshot，quote() 不再返回旧行情；新快照成功后恢复。原有单档 OrderBook 仍保持失败原子性，二者的序号协议不可混用。

PaperRuntime 当前直接接收 Quote。BookFeed 适配层需要自己将缺口/断线传播为停止交易命令或 watchdog，并重新获取快照；本平台没有暗含交易所网络重连协议。更多操作边界见 OPERATIONS.md。
